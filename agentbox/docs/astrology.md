## 一、這是什麼

「人生時間軸」是「人生電影院 Reelme」裡的進階功能，用兩種西洋占星的生命週期技法，把出生後到未來五年的重要時間窗排出來，它不是預測工具，也不是命運判定，而是一套固定的回顧架構，讓同一套規則套在每個人身上。

它會把每個時間窗放回你的 Facebook 貼文附近，讓你回頭看那段時間寫了什麼，也讓你知道占星傳統通常怎麼描述這個週期。

這個功能藏在「第二人生」裡的選填星盤步驟，只有放入你自己的 Facebook 匯出檔之後才會出現。

## 二、怎麼使用

### 1. 在網頁裡

首頁一開始看到的是我的示範電影，不會顯示出生資料表單，所以在那裡看不到人生時間軸，你要先放入自己的 Facebook 匯出檔。

操作步驟如下：

1. 按「交件：放入你的 FB 匯出檔」，載入你的 Facebook 匯出資料。
2. 按「第二人生」。
3. 在「一、星盤（選填，可以跳過）」輸入出生日期，出生時間，出生地點。
4. 出生時間如果不知道，可以勾選「不知道出生時間」。
5. 出生地可以從 42 個城市中選擇，也可以選「其他地點（自己填經緯度）」，輸入緯度，經度和固定 UTC 時差。
6. 按「排盤，說明我的命格」。
7. 在星盤下方的「人生時間軸」區塊，按「排出我的人生時間軸」。

計算時會出現進度列，通常需要 1 到 3 秒。

結果會出現在兩個地方：

- **第二人生面板**：先顯示摘要，再分成「已經走過的」和「接下來五年」，後一組會標示「占星傳統的說法，不是預測。」每個時間窗會有標題，日期，年齡，占星傳統中的兩句說明，以及那段期間最多兩篇你的貼文，預設只顯示重大時間窗，以及有對得上貼文的過去時間窗，按「顯示全部 N 個時間窗」可以展開全部結果，下方的「資料來源與可信度」會說明計算方式和比較結果。
- **放映廳的大銀幕**：顯示一張 1920×1080 的人生時間軸，有六條不同色彩的主題帶，一條「現在」線，以及有貼文對上的時間窗圓點，畫面也會顯示「N 個時間窗對得上（隨機時間段平均 M 個）」。

接著按「開始推演」時，分岔點之後的重大時間窗會以「同一片天空」加入 AI 提示，AI 會把虛構人生的轉折盡量放在這些時間窗附近，並在相關場景寫下一段不超過 20 個字的天空事件說明，這是同一片天空，不同的選擇。

### 2. 用命令列測試任何人的出生資料

測試者不需要 Facebook 匯出檔，也可以直接使用命令列工具，需要 Node.js 20 以上的版本，在專案的根目錄先安裝指定版本的天文函式庫：

```bash
npm install --no-save astronomy-engine@2.1.19
```

有出生時間和城市時，可以這樣執行：

```bash
node agentbox/tools/timeline.mjs --date 1990-05-01 --time 08:30 --city 台北
```

不知道出生時間時，加入 `--no-time`：

```bash
node agentbox/tools/timeline.mjs --date 1990-05-01 --no-time --city 倫敦
```

也可以直接輸入經緯度和時區：

```bash
node agentbox/tools/timeline.mjs --date 1975-12-24 --time 23:10 --lat 69.65 --lon 18.96 --tz Europe/Oslo
node agentbox/tools/timeline.mjs --date 1990-05-01 --time 08:30 --lat 25.03 --lon 121.56 --offset +8
```

`--cities` 會列出可用的城市名稱，`--all` 會連非重大時間窗也列出，`--json` 會輸出適合程式讀取的格式：

```bash
node agentbox/tools/timeline.mjs --cities
node agentbox/tools/timeline.mjs ... --all
node agentbox/tools/timeline.mjs ... --json
```

工具會直接讀取 `agentbox/static/index.html` 裡的計算引擎，所以命令列結果和網頁使用的是同一套程式，輸出包含計算後的 UTC 時間，太陽，月亮，ASC，MC，以及每個時間窗的第一個精確日期，通過精確點的次數，年齡，標題和涵蓋範圍，你可以拿這些結果和專業占星軟體比較。

## 三、怎麼計算

### 1. 星盤從哪裡來

星體位置由 Astronomy Engine 2.1.19 計算，它是開放原始碼軟體，採用 MIT 授權，作者是 Don Cross，位置使用當日的視地心黃經，採熱帶黃道。

宮位使用 Placidus，在 Placidus 無法計算的緯度，改用 Porphyry，時區使用瀏覽器內建的 IANA 時區資料庫，包含台灣和其他地區歷史上的日光節約時間，自訂地點則使用你輸入的固定 UTC 時差。

如果不知道出生時間，星盤會以當地中午排盤，不會計算 ASC，MC 和宮位，月亮的位置最多可能差大約 6 到 7 度。

我用 Swiss Ephemeris 做過比對，這是專業占星軟體常用的星曆，使用 pyswisseph 2.10.03，以及 `sepl_18` 和 `semo_18` 檔案，比對了 66 張出生星盤和全部十個星體，最大差異是海王星的 0.3 角分，太陽是 0.02′，月亮是 0.06′，ASC 和 MC 的差異小於 0.01 角分，1 角分是 1/60 度。

### 2. 兩種推算人生週期的技法

這裡使用兩種西洋占星傳統中的時間技法，每一條規則都事先固定，不會看完你的資料之後才挑選。

| 技法 | 星體或點 | 相位與對象 |
|---|---|---|
| 行運 | 木星 | 回歸，與本命太陽，ASC，MC 合相 |
| 行運 | 土星 | 回歸，與本命土星四分相和對分相，與本命太陽，月亮，ASC，MC 合相，四分相和對分相 |
| 行運 | 天王星 | 與本命天王星四分相和對分相，與本命太陽，月亮，ASC，MC 合相，四分相和對分相 |
| 行運 | 海王星 | 與本命海王星四分相，與本命太陽，月亮，ASC，MC 合相，四分相和對分相 |
| 行運 | 冥王星 | 與本命冥王星四分相，與本命太陽，月亮，ASC，MC 合相，四分相和對分相 |
| 次限推運 | 推運太陽 | 推運太陽換星座 |
| 次限推運 | 推運月亮 | 與本命 ASC，IC，DSC，MC 合相，月亮回歸 |
| 次限推運 | 推運太陽和月亮 | 推運新月，也就是推運太陽和推運月亮相遇 |

行運看的是慢速星體在真實天空中的位置，和出生星盤的位置比較，次限推運採用「出生後一天等於人生一年」的換算。

常見年齡只能當作例子，每張星盤都不同：

| 週期 | 常見年齡，大約 |
|---|---|
| 土星四分相 | 7，21，36 |
| 土星對分相 | 14 到 15，44 |
| 土星回歸 | 29，58 |
| 木星回歸 | 每 12 年左右 |
| 天王星對分相 | 40 到 42 |
| 海王星四分相 | 40 到 42 |
| 推運月亮回歸 | 27 左右 |

### 3. 時間窗怎麼定

每個星體的容許度都是 1 度，時間窗是星體進入精確相位前後 1 度的期間，不是只有精確發生的那一刻。

如果逆行造成多次通過，而這些精確通過相隔不到 400 天，就會合併成同一個時間窗，因此一個時間窗可能有 1 到 5 次精確通過，精確時間會用二分法細分，行運精確到 1 小時以內，次限推運精確到 3 天以內。

出生後非常早期的自我回歸，如果第一次精確通過在 3 歲以前，會被排除，從未真正到達精確相位的項目也會排除。

計算範圍從出生後一個月開始，到今天之後五年為止，最晚不超過 2035 年底，重大時間窗包括土星回歸，土星對分土星，天王星對分天王星，土星，天王星，海王星，冥王星和太陽，月亮，ASC，MC 的合相，四分相和對分相，推運太陽換星座，推運月亮合相 ASC，推運新月。

不知道出生時間時，會跳過月亮，ASC，MC 的時間窗，以及所有推運月亮時間窗，月亮一天大約移動 13 度，ASC 大約每 4 分鐘移動 1 度，如果沒有出生時間，這些項目不夠可靠。

一個 80 年的人生在 Node 中平均約 1.1 秒完成，最慢的測試是 2.3 秒。

## 四、解讀規則

時間窗本身只告訴你相位和日期，標題與文字說明來自一張事先寫好的規則表，表中共有 66 條規則，每個人使用完全相同的規則。

每條規則都有一個不超過 10 個字的標題，兩句以西洋占星傳統為基礎的說明，6 到 12 個可能出現在台灣 Facebook 貼文中的關鍵字，以及一個主題，六種主題各有自己的色彩，在畫面上形成六條色帶：

| 主題 | 對應內容 | 色彩呈現 |
|---|---|---|
| 結構 | 土星 | 金色 `#C9A96E` |
| 突破 | 天王星 | 淡藍色 `#9FB3CC` |
| 轉化 | 冥王星，推運太陽，推運新月 | 灰紫色 `#B98CA6` |
| 擴張 | 木星 | 鼠尾草綠 `#A9C08F` |
| 理想 | 海王星 | 藍色 `#8FA8C9` |
| 回顧 | 推運月亮 | 暖灰色 `#C4BDB1` |

三條規則的原文如下，和網頁上顯示的一字不差：

> **土星回歸**：土星回到出生位置，傳統上稱為成年禮。這段時間常重新確認工作、家庭與人生責任，建立接下來數十年的基礎。

> **天王星對分**：天王星與本命天王星相對，人生路線需要重新畫線。這段時間常突然換工作、搬家或結束舊循環，追求更真實的自己。

> **木星回歸**：木星回到出生位置，常帶來新一輪的擴展與機會。這段時間可能想出國、進修或擴大生活範圍，適合為未來做樂觀的規劃。

66 條規則先由 DeepSeek V4 Flash 草擬，再由 Kimi K3 審閱並修改其中 24 條，這兩個模型都在 GMI Cloud 上執行，最後由 Claude 檢查。

## 五、對照貼文，以及誠實的比較

### 1. 怎麼對照

每一個已經發生的時間窗，會查看時間窗前 120 天到後 120 天的貼文，隱藏貼文，少於 8 個字的短貼文，分享，連結，別人寫在你塗鴉牆上的貼文，生日祝福和封面照片變更都不會納入。

一個時間窗只有在以下其中一種情況成立時，才算「對得上」：

1. 那段期間有一篇貼文被分析為「人生轉折」。
2. 那段期間有一篇貼文包含這條規則至少兩個不同的關鍵字。

每個時間窗最多顯示兩篇貼文，符合條件的貼文會優先顯示。

### 2. 為什麼一定要比較

時間窗又長又多，這一點會讓「對得上」看起來比實際更有意義，以我的星盤來看，15 歲以後的日子，有大約 68% 落在重大時間窗裡，幾乎人生中的任何一段期間，都可能落在某個時間窗內。

所以只說「它對上了」不夠，我還要拿同樣長度的隨機時間段來比較。

對每個時間窗，我會在第一篇貼文到今天之間，隨機抽出 20 段相同長度的時間，隨機產生器使用固定種子，因此結果可以重現，頁面會顯示類似這樣的比較：

「已經走過的 30 個時間窗裡，13 個找得到內容對得上的貼文；拿同樣長度的隨機時間段來比，平均是 13 個。」

### 3. 我自己的結果

我使用自己的真實出生資料，以及 15 年的 Facebook 貼文做測試：

| 比較對象 | 結果 |
|---|---:|
| 全部時間窗 | 69 個 |
| 重大時間窗 | 47 個 |
| 在我第一篇貼文以前結束，不列入比較 | 32 個 |
| 我開始發文後的時間窗 | 30 個 |
| 30 個時間窗附近有貼文 | 30 個 |
| 30 個時間窗中真正對得上的 | 13 個，43% |
| 相同長度的隨機時間段，平均對得上 | 44% |

我也把自己的貼文拿去對照七位其他人的出生資料，測試不同星盤是否會在同一批貼文上得到類似結果：

| 星盤資料 | 和我的貼文對得上的比例 |
|---|---:|
| 台北 1965 | 11 / 28，39% |
| 倫敦 2001，不知道出生時間 | 4 / 10，40% |
| 紐約 1950 | 11 / 24，46% |
| 北京 2008 | 10 / 24，42% |
| Tromsø，69.65°N，1978 | 13 / 26，50% |
| 台中 1995 | 12 / 29，41% |
| 雪梨 1988 | 9 / 27，33% |
| 七人的平均 | 42% |
| 我自己的星盤 | 13 / 30，43% |

### 4. 這代表什麼

直接說結論，在我自己的資料上，我的時間軸沒有比隨機日期或陌生人的星盤更能對上我的人生，這和科學研究沒有發現占星能預測人生事件的結果一致。

所以，人生時間軸不是證據，也不是預測。

它還是有幾個比較實際的用途，它提供一套固定而共享的人生章節詞彙，例如土星回歸，四十歲左右的天王星對分，讓不同的人可以用同一套名稱談一段人生，它也能把你的 Facebook 貼文按時間窗整理，讓你從另一種角度回看自己寫過的東西。

對「第二人生」來說，它提供一個一致的轉折時鐘，真實人生和虛構人生看的是同一片天空，但可以做出不同選擇。

我把這個比較直接放在頁面裡，不把隨機結果和陌生人的結果藏起來。

## 六、驗證與測試

自動測試檔案是 `agentbox/tests/astro.test.mjs`，執行方式如下：

```bash
npm install --no-save astronomy-engine@2.1.19
node agentbox/tests/astro.test.mjs
```

目前結果是 314 項檢查通過，0 項失敗。

測試內容包括：

- 三張參考星盤，台北 1965，倫敦 1978，以及一張 2001 年星盤，和 Swiss Ephemeris 比較土星回歸，木星回歸，以及推運太陽換星座，土星回歸和木星回歸精確時間差在 2 天內，推運太陽換星座差在 5 天內，並且換到正確的新星座。
- 300 組隨機出生資料，其中大約 70% 有出生時間，大約 15% 是自己填經緯度的地點，包含高緯度地區，並使用固定 UTC 時差。
- 檢查時間窗排序，每個時間窗內都有精確通過，年齡不會是負數，每條規則都存在於規則表，未知出生時間時不會產生月亮，ASC，MC 時間窗，涵蓋率介於 0 和 1 之間。
- 如果計算範圍涵蓋 27 到 31 歲，應該會有土星回歸。
- 檢查規則文字，貼文篩選和計數，非同步版本是否和同步版本相同，以及最慢的星盤是否在 5 秒內完成。

GitHub Action 每次更新都會執行這組測試，而且會在建立 Docker 映像檔之前執行。

另外還有 Playwright 和 Chromium 的瀏覽器測試，使用我的資料和另外七組出生資料，實際走過星盤，人生時間軸，第二人生面板和放映廳的大銀幕，確認過程沒有頁面錯誤。

## 七、限制

- 這不是預測，也不是建議，不要拿它做醫療，財務，法律或感情決定。
- ASC 和 MC 的時間窗很依賴出生時間，出生時間差 4 分鐘，ASC 就可能移動約 1 度，慢速星體的時間窗可能因此差上數個月。
- 規則文字只是對占星傳統的一種解讀，其他占星師可能會用不同方式說明。
- 目前只有西洋熱帶占星，沒有中國占星，沒有恆星黃道，也沒有吠陀占星技法。
- 貼文對照只看得到你發在 Facebook 上的內容，很少發文的那幾年會看起來是空白的。
- 關鍵字使用台灣繁體中文，其他語言的貼文很少會對得上。
- 這是測試中的功能，目前只用上述案例測試，還需要更多其他人的真實出生資料，才會正式公布。

## 八、隱私

星盤和人生時間軸完全在你的瀏覽器裡計算，你的出生日期，時間和地點不會上傳，也不會儲存。

只有在你按「深入解讀命格」或「開始推演」時，文字才會送到 AI 模型。「深入解讀命格」會送出星體位置，星座，度數，宮位和相位，「開始推演」會送出分岔點附近的貼文，星體位置，以及分岔點之後重大時間窗的月份範圍和說明，但你的出生日期，時間和地點本身不會放進提示。

在 GMI Agentbox 上，模型在 GMI Cloud 上執行，在 Claude 裡則由 Claude 執行。

示範電影中不會顯示作者的出生資料。

## 十、回報問題

問題請到 [GitHub Issues](https://github.com/hansai-art/reelme/issues) 回報，請附上命令列輸出，使用 `--json` 最方便，也請附上你的占星軟體顯示的結果。

要公開完整的出生時間之前，請先想清楚，用一個接近的時間，或是取得當事人同意再貼，都可以。
